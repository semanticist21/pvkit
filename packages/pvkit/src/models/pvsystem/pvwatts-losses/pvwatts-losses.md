# pvwatts-losses — PVWatts system losses

Combined system loss from the ten PVWatts loss categories, as a fraction.

## Principle

`L_total = 1 − Π_i (1 − L_i)` over soiling, shading, snow, mismatch, wiring, connections,
LID, nameplate rating, age, availability loss (multiplied in that order, as pvlib) — the
same compounding as `combineLossFactors`, computed locally (no cross-module import).
Defaults are pvlib's / 100 (0.02, 0.03, 0, 0.02, 0.02, 0.005, 0.015, 0.01, 0, 0.03) →
0.1408, the PVWatts V5 default of 14.08 %. No validation, as pvlib: negative losses (gains)
are allowed and values over 1 give an out-of-range total.

**Deviation from pvlib:** pvlib takes and returns percent; pvkit takes and returns
fractions (0–1) so the result composes with `combineLossFactors` and the other loss models.
pvlib's `availability` is `availabilityLoss`.

## Reference

- **Spec:** A. P. Dobos, "PVWatts Version 5 Manual", NREL/TP-6A20-62641, 2014,
  doi:10.2172/1158421, https://www.nrel.gov/docs/fy14osti/62641.pdf (system losses).
- **Reference implementation:** `pvlib.pvsystem.pvwatts_losses` @ pvlib 0.16.1, every
  category passed explicitly; fixture inputs are pvlib's inputs / 100 and expected values
  are pvlib's result / 100.
- **Fixtures:** `pvwatts-losses-fixtures.json` (66 cases: defaults, all zero, one and all
  at 1, a negative loss, 60 random 0–0.3), generated by
  `scripts/fixtures/pvsystem-pvwatts.py`. The 0.1408 default is also asserted.
- **Tolerance:** `1e-15` absolute (fraction). pvlib's `(1 − Π(1 − l/100))·100 / 100` vs our
  `1 − Π(1 − f)` differs by at most a few ULP of the result (all `− × /`); margin for fused
  multiply-adds.
